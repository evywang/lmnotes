# v0.5.0「效率与分发」设计 — 媒体任务队列 + 模板 + 导出 + macOS

> 对应 roadmap v0.5.0 迭代。本文是实施级设计。制定日期:2026-08-29,
> 前置:v0.4.0(音视频转录与视觉描述就位后,任务队列才有承载对象)。

## 目标与定位

```
FR-MEDIA-04 任务队列:    媒体处理(转录/描述)后台化——pending/running/done/failed,可重试可取消
FR-CAP-09(顺带收编):     长音频/视频离线后台转录,完成通知(不再 60s 超时即弃)
FR-CAP-08 模板系统:      templates/ 目录 + frontmatter 占位符 + 新建笔记选模板
FR-STORE-05 导出:        一键 zip 导出 / 初始化 git 仓库
macOS 打包:              release 矩阵加 macOS(whisper/ffmpeg 从源码构建,签名公证)
```

核心是**任务队列**(L 级):它把 v0.4 里"同步等待转码+转录"的长媒体操作变成后台任务,
是效率主题的地基;其余三项(S/M)搭车。

---

## 关键现状(已核实)

- **媒体处理目前全是同步 invoke**:`create_voice_note`/`create_media_note`(v0.4)在命令内
  串行完成 归档→转录→建 concept,whisper.cpp 60s 超时保护(超时=任务失败,无重试)。
- **SQLite 已有任务型表先例**:`suggestions` 表(status 列 + created_at/applied_at,
  schema.rs:46-58),`chat_history` 同款模式——任务表照此风格加即可;迁移方式照
  v0.3 的 `ALTER` 容错惯例(新表则只需 CREATE IF NOT EXISTS,无迁移问题)。
- **SqliteIndex 是 Mutex<Connection> 单连接**:所有方法锁内短事务,加任务表的
  CRUD 方法不与现有竞争模式冲突。
- **Tauri 事件通道已用**:`whisper-model-progress`/`chat-chunk`(v0.2 起)——任务状态
  变更走 `app.emit("media-task-update", ...)` 同一模式。
- **前端已有轮询先例**:SuggestionCenter 定时拉 list_suggestions。
- **模板零基础**:grep `template` 前端 0 命中;`create_note` 命令(commands.rs)是唯一
  建笔记入口(frontmatter 手写格式串)。
- **导出零基础**:`zip` crate 不在依赖;`git` CLI 在用户机器普遍存在(本仓库开发者视角),
  但不能假设终端用户有——git init 需探测+降级提示。
- **macOS 的 sidecar 现实**(v0.2 打包期已查明):ggml-org/whisper.cpp release **无 macOS
  原生预编译**(只有 xcframework/iOS 向 + ubuntu + windows);ffmpeg 无 BtbN 对应物。
  → macOS 必须在 CI **从源码构建** 两个 sidecar(cmake/make,约 +6-10min CI 时长)。
- **签名公证**:需要 Apple Developer 账号($99/年)+ 证书入 GitHub Secrets;无账号则
  分发"未签名 dmg"(用户右键打开绕 Gatekeeper,体验打折但可用)——设计按可选层处理。

## 任务分解

### A. FR-MEDIA-04 媒体任务队列(T1–T4)

#### T1 · 核心层:任务表 + CRUD

**`crates/lmnotes-core/src/index/schema.rs`**
```rust
pub const CREATE_MEDIA_TASKS: &str = "
CREATE TABLE IF NOT EXISTS media_tasks (
    id          TEXT PRIMARY KEY,        -- mt_<ts>_<4crockford>
    kind        TEXT NOT NULL,           -- transcribe | describe
    asset_rel   TEXT NOT NULL,           -- /assets/{audio|video|img}/xx/hash.ext(输入)
    mime        TEXT NOT NULL,
    duration_ms INTEGER,                 -- 可空(图片无)
    language    TEXT,                    -- 可空
    status      TEXT NOT NULL,           -- pending|running|done|failed|cancelled
    error       TEXT,
    result_path TEXT,                    -- 产出笔记路径(transcripts/… 或 descriptions/…)
    created_at  INTEGER NOT NULL,
    updated_at  INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_media_tasks_status ON media_tasks(status);
";
#[derive(Debug, Clone, Serialize)]
pub struct MediaTask { /* 上列字段 */ }
```
**`sqlite.rs`** inherent 方法(不入 IndexBackend trait——媒体任务是应用层概念):
`insert_task / update_task_status(id, status, error?, result_path?) / list_tasks(filter) /
pending_tasks(limit)`。init_schema 挂入 execute_batch。

**测试(TDD)**:CRUD round-trip、状态迁移落库、list 过滤(pending-only/全部)——in_memory。

#### T2 · 壳层:后台 worker + 命令

**新文件 `apps/desktop/src-tauri/src/media_tasks.rs`**
```rust
/// 媒体任务后台 worker:启动时 spawn,循环 = 拉 pending → 逐个执行 → 更新状态 → emit。
/// 执行体复用现有编排:transcribe 走 transcribe_with_fallback + build_transcript_concept;
/// describe 走 vision describe + image-desc concept。
/// 并发=1(whisper.cpp 单进程吃满 CPU,串行足够;留 max_concurrent 常量)。
pub fn spawn_worker(app: AppHandle, /* indexer/sqlite/registry/routing/guard Arc 克隆 */)
```
- 循环节奏:有 pending 连续处理;空闲 `tokio::time::sleep(2s)`;每次状态变更
  `app.emit("media-task-update", &task)`。
- **长音频解禁**:任务化后 whisper 子进程超时从 60s 放宽到 15min(命令内联路径保持 60s
  不变——两套常量,注释说明);FR-CAP-09 就此收编。
- 失败自动重试 1 次(网络类错误),再败标 failed 留手动重试。
- **命令**:`enqueue_media_task(asset_rel, kind, mime, duration_ms?, language?)`(v0.4 的
  `create_media_note` 改为薄封装:归档→入队→**立即返回** 占位提示路径或空,
  前端由事件 `media-task-update`(status=done, result_path)打开笔记)、
  `list_media_tasks(status?) -> Vec<MediaTask>`、`retry_media_task(id)`(failed→pending)、
  `cancel_media_task(id)`(pending/running→cancelled;running 的取消=杀子进程,
  通过 worker 持有的 KillHandle——第一版可只允许取消 pending,running 取消记不做)。
- **语音入口策略(VoiceCapture 速记场景)**:短录音仍走同步 `create_voice_note`
  (秒级返回,体验不变);**仅当** duration > 60s 或用户在设置勾选"长媒体走后台"时入队。
  设计理由:速记要即时反馈,队列是给长媒体的。

**测试**:worker 的状态机纯函数部分(决定 enqueue vs inline 的阈值函数、重试判定)单测;
执行体集成靠手动。

#### T3 · 前端:任务中心

**新文件 `apps/desktop/src/voice/MediaTasks.tsx`**(挂设置页 + 侧栏 🕘 入口)
- 列表:kind 图标(🎙 转录 / 🖼 描述)+ 资源名 + 状态徽章(pending 灰 / running 转圈 /
  done 绿 / failed 红)+ 耗时;`listen("media-task-update")` 实时刷新 + 30s 兜底轮询。
- done 条目点击 → `setActivePath(result_path)` 打开产物;failed 显示 error 摘要 +
  「重试」按钮;pending 有「取消」。
- i18n:`tasks.*` 约 12 键。

#### T4 · 衔接 v0.4 的媒体入口

- Editor 拖拽/粘贴音视频:按 T2 策略分流(短同步/长入队);入队后状态条提示
  「已加入后台任务」+ 打开任务中心入口。
- 设置页「长媒体走后台」开关(config.media.background_threshold_sec,默认 60)。

### B. FR-CAP-08 模板系统(T5)

**后端**
- `list_templates() -> Vec<TemplateInfo{name, path, title}>`:扫 `{vault}/templates/*.md`
  (目录不存在返回空;templates/ 本身是普通 concept 目录,可被索引——不特殊排除)。
- `create_note_from_template(template_path, title, parent_dir?) -> String`:
  读模板 → 占位符替换 → 复用 `create_note` 的落盘逻辑(重构出私有 `write_new_note(path, content)`)。
- **占位符**(正则一次性替换):`{{title}}`(用户输入)、`{{date}}`(YYYY-MM-DD)、
  `{{time}}`(HH:mm)、`{{datetime}}`(ISO 本地)。未识别占位符保留原样(不吞)。
- **测试**:占位符替换纯函数 4-5 例(含未识别保留、重复出现全替换)。

**前端**:新建笔记流程(App.createNote / FileTree.createNoteInDir)在输入标题的
  PromptDialog 上加模板下拉(None + list_templates);选中则改调 create_note_from_template。
  i18n 3-4 键。

### C. FR-STORE-05 导出(T6)

**后端**
- `export_vault_zip(dest_path) -> Result<u64>`:**新依赖 `zip = "2"`**(deflate 默认特性,
  纯 Rust)。walk vault(`walk_and_index` 同款递归,**排除 `.lmnotes/`** 派生数据)→
  逐文件入 zip(流式 writer,进度 emit `export-progress`)→ 返回字节数。
- `init_git_repo() -> Result<(), String>`:探测 `git --version`(PATH);有 → 在 vault 根
  `git init` + 写 `.gitignore`(`.lmnotes/`)+ 首次 `git add -A && git commit -m "init"`(无
  user.name 时 `commit` 会败——降级为只 init+gitignore,提示用户配置);无 git → 返回指引性错误。
- **测试**:zip round-trip(tempfile 建假 vault → 导出 → zip crate 读回断言文件集与排除项);
  git 探测纯函数。
- **前端**:设置页「数据」小节:导出(plugin-dialog `save` 选目的地)带进度;
  「初始化 git 仓库」按钮 + 结果反馈。i18n 4-5 键。

### D. macOS 打包(T7,含 spike)

- **T7a Spike(先行,半天)**:CI macOS runner 上 `brew install cmake` +
  `git clone whisper.cpp && cmake -B build -DWHISPER_NO_SERVER=ON ... && make whisper-cli`,
  ffmpeg 用 `brew install ffmpeg` 后**拷静态化的可行性验证**——brew ffmpeg 是动态链接
  (dylib 路径问题),预期结论:ffmpeg 也需源码构建(`--enable-static --disable-shared`,
  仅 mp3/aac/webm/wav 解码器,约 -70% 体积)。Spike 产出构建脚本,不通则本项降级
  "macOS 无本地 STT(仅云端)",文档明示。
- **T7b Workflow**:`release.yml` matrix 加 `macos-latest(target aarch64-apple-darwin)`;
  新 `.github/scripts/build-sidecars-macos.sh`(源码构建两件套 → binaries/-aarch64-apple-darwin);
  `sidecar-macos.json`(resources `*.dylib`——若动态)。产物 dmg。
- **T7c 签名公证(可选层)**:Secrets 有 `APPLE_CERTIFICATE` 系列时启
  `codesign --deep --options runtime` + `xcrun notarytool`;无则跳过并在 Release 说明
  "首次打开需右键→打开"。**无开发者账号也能发**,不阻塞。
- 验证:tag 触发 CI 全绿 + 本地(如有 mac)安装冒烟;无 mac 则以 CI 产物存在性 +
  dmg 挂载(linux 上 `7z`/`hdiutil` 不可用,仅 CI 自检)为验收底线,如实标注。

## 风险与对策

| 风险 | 对策 |
|---|---|
| worker 与命令并发写库 | 单连接 Mutex 串行化;任务状态更新是短事务 |
| 应用退出丢 running 任务 | worker 退出钩子把 running 重置 pending(启动时也做一次兜底扫描) |
| 长任务失败静默 | failed 必进任务中心红标 + 事件;重试一键 |
| zip 大库内存 | 流式 writer + 逐文件 64KB buffer,不全量入内存 |
| brew/git 不存在 | 全部探测式降级 + 明确错误文案(含指引) |
| macOS 源码构建超 CI 时长 | 仅装必需组件;ffmpeg 精简 codec;超时则 matrix 拆 job 缓存构建产物(actions/cache) |
| 无 Apple 账号 | 签名做可选层,不阻塞发布 |

## 手动验证清单

1. 拖 10 分钟 mp3 → 立即返回 + 任务中心出现 running → 完成后点开 transcript 笔记。
2. 任务中断网重试一次自动恢复;再断网彻底 failed → 任务中心手动重试(网恢复后)成功。
3. 退出应用时 running 的任务 → 重启后自动回 pending 续跑。
4. templates/ 放会议模板(含 {{title}}/{{date}})→ 新建笔记选它 → 占位符正确替换。
5. 导出 zip → 解开与 vault 一致且**无 `.lmnotes/`**;git init 后 vault 成为可提交仓库。
6. (若推进 T7)push tag → CI 三平台产物齐,macOS dmg 可安装、语音本地引擎可用。

## 明确不做(本版)

- running 任务的强杀取消(只取消 pending;杀子进程的 KillHandle 管理留后续)。
- 任务优先级/并行度配置(并发=1 写死)。
- 视频关键帧(FR-MEDIA-03)、移动端、Obsidian 导入、每日回顾——维持 P2 押后。
- 自动定时 git 提交(只做初始化;自动化属同步主题,未立项)。
