# v0.4.0「多库与媒体」设计 — 多 Vault + 音视频转录 + OCR/视觉描述 + 语音打磨

> 对应 roadmap v0.4.0 迭代。本文是实施级设计:每项含现状核实、任务分解、签名、测试与风险。
> 制定日期:2026-08-29。基于 v0.3.0 后的代码现状(分支 feat/voice-input)。

## 目标与定位

四个功能,一条主线:**让"库"和"媒体"成为一等公民**——

```
FR-STORE-01 多 Vault:      多库管理/切换(config 记 last_vault,重启生效)
FR-CAP-04  补全:           拖拽/粘贴 音频+视频 → 归档 → 自动转录(复用 v0.2 编排)
FR-MEDIA-02 OCR/视觉描述:  图片 → 多模态 LLM → type: image-desc concept(ADR-0005 预留的 VisionCap)
语音打磨:                   push-to-talk(按住说话) + 模型下载断点续传
```

依赖关系:四项互相独立,可任意顺序/并行。音视频转录与 OCR 都复用 v0.2 建立的
sidecar(ffmpeg/whisper)+ ADR-0005 护栏体系,增量小。

---

## 关键现状(已核实)

- **vault 双硬编码**:`commands.rs::vault_root()` 与 `lib.rs::vault_dir()` 都返回
  `~/.lmnotes/default`;**全 shell 层 21 处调用、集中在 2 个文件**(commands.rs / lib.rs)。
  索引(`.lmnotes/index.sqlite`)、watcher、MCP server 都在 `run()` 启动期绑定该路径。
- **MCP server 启动期绑定 vault**(`lib.rs:183-192` 构造 `LmnotesMcpServer` 时传入 dir +
  engine/meta 等具体 Arc)——热切换 vault 需要重建它,代价高。
- **`tauri::AppHandle::restart()` 存在**(tauri 2.11.3 `app.rs:588`,`-> !`):"切库即重启"可行。
- **config 全局于 `~/.lmnotes/config.json`**(与 vault 无关),天然适合存 vault 清单。
- **Editor 媒体入口只收图片**:`Editor.tsx::handleFiles` 里 `if (!f.type.startsWith("image/")) continue;`
  ——音频/视频被显式跳过。`archive_binary(data, ext, kind)` 已参数化 kind(img/audio),扩 video 是一行。
- **`create_voice_note` 编排可复用**(commands.rs):归档→护栏→转录(含本地降级)→transcript
  concept→索引+建议。视频差异仅在"先抽音轨"(ffmpeg `-vn`)。
- **whisper.cpp CLI 实测支持 flac/mp3/ogg/wav,不支持 webm/video**(v0.2 打包期验证);
  ffmpeg sidecar 已随包分发。
- **VisionCap 在 ADR-0005 §1 是预留 trait**(与 TranscribeCap 同级),`Capabilities` bitflags
  尚无 VISION 位。`Frontmatter.resource` + `type: image-desc`(PRD §3.5)格式已定义。
- **Ollama chat 支持图片**(native `/api/chat` 消息里 `images: [base64]`);OpenAI 兼容走
  `content` 多部件(`image_url` data URI)。二者形状不同→ 需按 provider 分别实现。
- **下载无断点续传**:`download_whisper_model` 直接写 `.part` 后 rename,中断重下;
  HF 直链支持 HTTP Range(测试文档 TC-M13 已记为已知限制)。
- **VoiceCapture 是 click-start/stop**(`start()/stop()` 两个函数,recorder/timer 信号齐备),
  push-to-talk 只需把"按下/松开"映射到这两个函数。

## 任务分解

### A. FR-STORE-01 多 Vault(T1–T3)

#### T1 · 配置层:vault 清单 + 当前库

**`llm_config.rs`**
```rust
pub struct Config {
    // ...现有字段...
    /// 已登记的 vault 目录(绝对路径)。v0.4 起用户可多库。
    #[serde(default)]
    pub vaults: Vec<String>,
    /// 启动时打开的 vault(绝对路径)。缺省/失效时回退 ~/.lmnotes/default。
    #[serde(default)]
    pub last_vault: Option<String>,
}
```
- `Default`:`vaults = [~/.lmnotes/default 的字符串]`,`last_vault = None`。
- 序列化向后兼容:`#[serde(default)]` 使老 config.json 无痛升级。

#### T2 · 路径解析收口 + 切库命令

- **`vault_root()`/`vault_dir()` 双实现收口**:lib.rs 与 commands.rs 各自拼 `~/.lmnotes/default`
  的 21 处调用不动签名,内部改为读同一来源。新增 `llm_config::current_vault() -> PathBuf`:
  `config.last_vault`(存在且目录有效)→ 回退 `~/.lmnotes/default`;两个函数改为委托它。
  **启动期一次解析、进程内不再变**(配合重启式切换,避免 RwLock 侵入 21 处)。
- **新命令**:
```rust
#[tauri::command] pub fn list_vaults() -> Vec<VaultInfo>            // {path, name(目录名), note_count? 免}
#[tauri::command] pub fn add_vault(path: String) -> Result<(), String>   // 校验目录/可空;入 config.vaults
#[tauri::command] pub fn remove_vault(path: String) -> Result<(), String> // 仅移出清单,不删数据
#[tauri::command] pub async fn switch_vault(app: AppHandle, path: String) -> Result<(), String>
// ① 校验在 vaults 内 ② config.last_vault = path;save() ③ app.restart()
```
- **`app.restart()` 方案的理由**(设计决策,记入 ADR-0008):热切换需重建 indexer/engine/
  watcher/MCP 五组 Arc + 重挂载 Tauri State,侵入面大且易留悬挂引用;重启式切换 3 行搞定、
  语义绝对干净(索引/ watcher/MCP 全部天然重建)。代价是切换要等 2-3 秒重启——对
  "库"这种低频操作完全可接受。Obsidian 1.x 初期同样如此。

#### T3 · 前端:设置页「库」小节 + 侧栏指示

- ProviderSettings 顶部加「📚 库」小节:当前库(路径,只读)+ 库列表(radio 当前项)+
  「添加库」(plugin-dialog 目录选择 → add_vault)、「移除」(confirm 后 remove_vault)、
  「切换」(confirm 提示将重启 → switch_vault)。
- 侧栏底部显示当前库名(目录名),点击跳设置。
- i18n:`vault.*` 约 10 键(中英)。
- **测试**:config serde 向后兼容(老 JSON 无 vaults 字段可解析)、`current_vault` 回退逻辑
  (last_vault 失效/None 两例)。switch/restart 属集成行为,手动验证。

### B. FR-CAP-04 音视频拖拽/粘贴转录(T4–T5)

#### T4 · 后端:`create_media_note` 命令

**`commands.rs`**(紧邻 create_voice_note,复用其编排)
```rust
#[tauri::command]
pub async fn create_media_note(
    data: Vec<u8>, ext: String, mime: String,       // 原始文件
    kind: String,                                    // "audio" | "video"
    duration_ms: Option<u64>, language: Option<String>,
    /* indexer/sqlite/registry/routing/guard_cfg States 同 voice */
) -> Result<String, String>
```
- 归档:`archive_binary(&data, &ext, kind)`(kind 泛化,video 落 `assets/video/`,复用哈希分桶)。
- **视频**:ffmpeg 抽音轨 `ffmpeg -i in -vn -ac 1 -ar 16000 -c:a pcm_s16le out.wav`
  (whisper_cpp.rs 已有 `run_ffmpeg_transcode`,加 `-vn` 参数即复用)→ 转录走音频路径。
- 转录:直接调 `transcribe_with_fallback`(云优先/本地兜底/护栏,与 voice 完全一致)。
- concept:`type: transcript`,`resource` 指向**原始视频/音频**;`extra.mime` 存原始 mime;
  `transcribed_by` 同 voice;`tags: [media]`(voice 流程仍是 `[voice]`,可区分)。
  落 `transcripts/`。
- 索引 + spawn 建议:同 voice 分支。
- **与 create_voice_note 的关系**:抽公共私有函数 `build_transcript_concept(...)` 供两者
  调用,避免复制 frontmatter 组装逻辑。

#### T5 · 前端:Editor 媒体入口放开

- `Editor.tsx::handleFiles` 分支:
  - `image/*` → 现有 insert_image 路径(不变,另见 C 部分 OCR 联动);
  - `audio/*`、`video/*` → `create_media_note`(bytes 直传;视频无时长信息则 `duration_ms: None`)
    → 成功后 `setActivePath(新笔记)` 打开(需向 Editor 传 `onNavigate`,App 已有该 prop 模式)。
- 拖拽/粘贴共用 handleFiles,一处改动双入口生效。
- busy 指示:状态条「转录中…」(复用 voice 的处理文案;大文件转码+转录可达分钟级,
  进度反馈留 v0.5 任务队列,本版转圈+可继续编辑其他笔记——invoke 是异步的,不阻塞 UI)。
- **测试**:后端 `build_transcript_concept` 的 frontmatter 组装单测(kind/tags/resource 断言);
  `run_ffmpeg_transcode` 加 `-vn` 后的参数单测(仿 build_whisper_cmd 的 Debug 断言)。

### C. FR-MEDIA-02 OCR/视觉描述(T6–T8)

#### T6 · 核心层:VisionCap(ADR-0005 预留位落地)

**`crates/lmnotes-core/src/llm/provider.rs`**
```rust
bitflags! { ... const VISION = 1 << 3; }

#[derive(Debug, Clone)]
pub struct ImageInput { pub bytes: Vec<u8>, pub mime: String }   // 单图,够用

/// 视觉描述能力(ADR-0005 §1)。OCR 不做专用管线——通用视觉模型描述已覆盖文字转写。
#[async_trait]
pub trait VisionCap: LlmProvider {
    async fn describe(&self, image: ImageInput, model: &str, prompt: Option<&str>) -> Result<String>;
}
```
- 默认 prompt:「用中文详细描述这张图片的内容;若图中含有文字,先逐字转写(保留原文语言),
  再描述版面/图表结构。」

#### T7 · Provider 实现 ×2

- **`openai.rs`**:`impl VisionCap for OpenAiProvider`——chat/completions 的 `content` 用
  多部件数组 `[{type:"text",text},{type:"image_url",image_url:{url:"data:{mime};base64,{b64}"}}]`。
  wiremock 测试:断言请求体含 image_url 部件、解析文本回复。
- **`ollama.rs`**:`impl VisionCap for OllamaProvider`——`/api/chat` 消息加 `"images":[b64]`
  (Ollama 原生形状)。wiremock 测试同上形状断言。
- 路由:`Task::Vision` 新变体 + `RoutingConfig.vision: Option<ProviderRefSer>` + build 注册
  (谁配了 vision_model 谁注册;OpenAi 加 `vision_model: Option<String>`,Ollama 加可选
  `vision_model`——llama3.2-vision/llava 类)。默认 None(视觉默认关,符合本地优先)。
- **护栏**:图片 bytes 不可扫描,同语音路径——`check(guard, kind, "", false)`,
  云端受 `cloud_allowed` 门控。ADR-0005 简化的同一先例。

#### T8 · 编排:`describe_image` 命令 + 图片描述 concept

**`commands.rs`**
```rust
#[tauri::command]
pub async fn describe_image(
    asset_rel: String,     // /assets/img/xx/hash.png(已归档的)
    language_hint: Option<String>,
    /* registry/routing/guard + indexer/sqlite(建 concept 后索引) */
) -> Result<String, String>   // 返回 image-desc 笔记路径
```
- 读图 bytes(vault 内,路径前缀校验同 read_snapshot 模式)→ `vision_for(Task::Vision)` →
  护栏 → `describe()` → 建 `type: image-desc` concept(PRD §3.5:`resource` 指图、
  `transcribed_by: {model}@{pid}`、存 `descriptions/`)→ 索引+spawn 建议 → 返回路径。
- **前端联动**(Editor.handleFiles 图片分支):`insert_image` 成功插入链接**后**,
  检测路由是否配了视觉(Task 未配则跳过,静默)→ 后台 fire-and-forget 调 `describe_image`
  → 完成后 console/建议中心可见(image-desc 会进索引,图谱可连)。**不弹窗打扰**;
  需要时用户从图链笔记点开描述笔记。
- **测试**:两个 provider 的 VisionCap wiremock(2-3 例);命令层 frontmatter 组装单测。
  (describe_image 全链路集成 → 手动。)

### D. 语音打磨(T9)

- **Push-to-talk(按住说话)**:`VoiceCapture.tsx` 录音键改 `onMouseDown={start} onMouseUp={stop}
  onMouseLeave={stop}`(鼠标离开视作松手,防悬挂);键盘空格按住可选(本版不做,记手动验证
  清单外)。移动语义:松开即停止并转录,与现状 stop() 一致;UI 文案改「按住说话」。
- **断点续传**:`download_whisper_model` 增强——启动时若 `{dest}.part` 存在,发
  `Range: bytes={size}-`;响应 206 → 追加写(`OpenOptions::append`);200(服务器不支持)→
  重头。完成照旧 rename。`.part` 损坏校验:若最终 Content-Length 与已下+新下不符 → 报错重试。
  单测:Range 头构造纯函数 + 206/200 分支逻辑(用 wiremock 模拟两态)。
- i18n:`voice.holdToRecord` 等 2-3 键调整。

## 实现顺序与提交切分

1. **T1–T3 多 Vault**(配置+命令+设置 UI)→ 提交① `feat(vault): multi-vault management with restart-on-switch (FR-STORE-01)`
2. **T4–T5 媒体转录** → 提交② `feat(media): audio/video drop-to-transcribe (FR-CAP-04)`
3. **T6–T8 视觉描述** → 提交③ `feat(vision): VisionCap + image description notes (FR-MEDIA-02)`
4. **T9 打磨** → 提交④ `feat(voice): push-to-talk + resumable model download`
5. 文档(ADR-0008 多库决策 + user-manual + roadmap 状态)→ 提交⑤ `docs:`

每步门禁:fmt/clippy/test(--workspace)+ tsc/build 全绿再提交。

## 风险与对策

| 风险 | 对策 |
|---|---|
| restart 切库丢未保存编辑 | switch 前前端检查 dirty → confirm 提示保存;防抖保存 800ms 本就快 |
| 大视频转录阻塞命令通道 | invoke 异步不卡 UI;真正的后台队列化是 v0.5 任务队列,此处文档明示衔接 |
| 云视觉模型质量参差/误 OCR | describe 输出进独立 image-desc 笔记,可删可改,不污染原图笔记 |
| Range 续传遇不支持的服务器 | 200 分支重头下;单测覆盖两态 |
| vision_model 配置门槛 | 默认关;设置页给 Ollama llava 一键建议文案 |
| 多库后索引/快照路径混淆 | 全部相对 vault_root 派生,收口后无绝对路径残留(grep 断言) |

## 手动验证清单

1. 设置添加第二个空目录为库 → 切换 → 应用重启后侧栏/文件树为新库;切回原库数据无损。
2. 拖一个 .mp3 到编辑器 → 生成 transcript 笔记(音频归档+转录);拖 .mp4 → 同样,且 `resource` 指向视频。
3. 断网状态下拖 .mp3 → 本地 whisper.cpp 兜底(复用 v0.2 降级)。
4. 配好视觉模型后粘贴截图 → 图片插入 + 稍后 `descriptions/` 出现 image-desc 笔记(含图中文字转写)。
5. 未配视觉模型时粘贴图片 → 只插图,无报错。
6. 语音浮窗按住按钮说话、松开 → 自动转录;下载 small 中途关应用重开 → 续传而非重下。

## 明确不做(本版)

- 热切换 vault(不重启)——记 ADR-0008 Alternatives。
- 视频关键帧抽取(FR-MEDIA-03,P2)。
- 专用 OCR 引擎(tesseract)——通用视觉模型已覆盖,留观察。
- 任务队列/进度条(v0.5 主题)。
